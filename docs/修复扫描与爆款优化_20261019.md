## 三、一键生成爆款短剧优化意见

### 一键（工程层）
1. **一键入口确认**：从小说到成片应是一条命令/一个按钮（检查是否已有 `一键生成` CLI/前端入口，没有就补 `python tools/one_shot.py <小说> [--episodes N]`）；
2. **验收门开硬门**：爆款流水线设 `MJSCXT_ACCEPTANCE_GATE=block`——乱码率超 20% 自动拦截并**自动重配**（现有逻辑只记录不阻断，量产会带病出片）；
3. **失败自愈**：成片为空（如现在的 12 字节文件）应在 pipeline 内直接判定失败并触发重跑，不能落空文件。

### 爆款（内容工程，零成本基于已有字段）
| 建议 | 落地方式 | 依据字段 |
|---|---|---|
| 开场 3 秒钩子 | 首镜优先"反常画面"型钩子（非场景钩子）；前 3 镜完成 反常→点名冲突→情绪升级 | beat/③-补 |
| 短剧节奏审计 | 生成后自动统计：触发节拍 ≤3 镜、高潮落在 70-80%、每集 ≥3 次情绪起伏 | beat/emotion 字段现成 |
| 集尾必钩 | 每集最后 1 镜强制 `caption{kind:"悬念"}`，保连播率（短剧核心指标） | caption kind=悬念 已有 |
| 人设记忆点 | 主角配置"标志性台词/动作"，跨集强制复用 | characters bible |
| TTS 情绪密度 | 确认 `emotion` 字段已传入 TTS instruct（爆款靠情绪密度，不只是念对字） | emotion/dialogue |
| 数据闭环 | analytics 目录接真实完播/留存数据，回喂选题与开场 | analytics/ |

### 优先级
1. 配置 project_rules（10 分钟，激活 A2/L2）；
2. 跑通一集端到端拿 acceptance.json + 新成片（补上缺口 3）；
3. 开硬验收门 + 集尾悬念规则（爆款连播率立竿见影）。

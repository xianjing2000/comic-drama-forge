## B-4　per-kind 提示词增强跳过开关

### 改了什么
- `app/config.py`（`PROMPT_MODEL_REVIEW_ENABLED` 之后）新增：
  `PROMPT_ENHANCE_SKIP_KINDS = tuple(...)`，读环境变量 `MJSCXT_PROMPT_ENHANCE_SKIP_KINDS`（逗号分隔），**默认空**。
- `app/prompt_enhance.py`：新增模块级 `_SKIP_KINDS`；在 `enhance_prompt()`（early-return 处）与 `model_review()` 各加一处「命中即跳过」。

### 怎么用（默认零行为变更）
```bat
REM 只关分镜的增强/复审（省前置段 ~56s/镜 ≈ 43 分钟/集）
set MJSCXT_PROMPT_ENHANCE_SKIP_KINDS=storyboard
REM 资产/尾帧/H3 不受影响
```
- ⚠️ **缓存键**：关掉后「增强前/后」是两条不同的内容寻址键 → 首次会有一轮重算（不影响产物续跑）。
- ⚠️ 这是**质量 tradeoff** 开关：日志显示该层常「本次不增强」（跑了时长却没改字），净质量损失可能接近 0，但请按项目惯例**先小范围复验**（取 A-3 的阶段耗时数据 + 抽样看画面）。

### 验证 / 回退
- 验证：设上环境变量后跑 1 镜，日志应出现 `该类型已按配置跳过增强`；不设则行为与改前一致。
- 回退：删环境变量（或删 `_SKIP_KINDS` 两处判断）。

## B-5　内存 / 显存护栏（只读探测 + 告警）

### 改了什么
- `app/config.py`（`KEEP_MODEL_LOADED` 之后）新增：`GPU_GUARD_ENABLED`（默认 True）、`GPU_GUARD_RAM_WARN_GB`（默认 6）、`GPU_GUARD_VRAM_WARN_MB`（默认 800）。
- `app/gpu_task_gate.py`：新增 `_probe_mem()`（Windows 走 `GlobalMemoryStatusEx`；Linux 读 `/proc/meminfo`；显存走 `nvidia-smi`，5s 缓存）、`_mem_guard()`；`run_gpu_task()` 开始前调用（**只告警、不硬拦**）；`status()` 追加 `memory` / `memory_warn` / `guard_enabled`。

### 行为
- 每次 GPU 任务开始前探测；低于阈值 → 一条 `⚠ ... 资源偏紧` warning（给运维处置窗口）。
- `/api/status` 的 `gpu_gate` 增加 `memory:{ram_free_gb,ram_total_gb,vram_free_mb,vram_total_mb}` 与 `memory_warn`(bool)。
- **fail-open**：探测失败（无 nvidia-smi / ctypes 异常）一律静默返回 {}，绝不阻断任务。

### 为什么是「告警」而不是「暂停」
原方案提到「<6GB 暂停非必要前置段」——**硬暂停**在无测试环境下有死锁/误伤风险，故本轮先做**只读探测 + 告警 + 状态可见**（安全子集，零行为风险）。硬暂停/排队是可选的下一步。

### 验证 / 回退
- 验证：跑一个 GPU 任务，看日志有无资源告警；`curl http://127.0.0.1:5211/api/status` 看 `gpu_gate.memory`。
- 回退：`MJSCXT_GPU_GUARD=0`（一键关）。

## E-1　SSE 进度推送

### 后端（已落地）
- `app/routes/status_api.py` 新增 `GET /api/events/stream`：`stream_with_context` + `text/event-stream`，每秒把 `job_state.generation_state` 快照推送（**变化才推 data，否则发 `: keep-alive` 心跳**）。含每个任务 `status/progress/phase/live/…`。Waitress 长连接已就绪（`serve.py` channel_timeout=1800）。
- **只读、fail-open**；不新增 blueprint（挂在已注册的 `status_api_bp` 上），改动面最小。

### 前端（hook 已就绪；迁移留作增量）
- 新增 `frontend/src/hooks/useEventStream.ts`（**新文件、零副作用**）：
  ```tsx
  const { snapshot, connected } = useEventStream();
  const task = snapshot?.tasks.find((t) => t.task_id === taskId);
  // task?.status / task?.phase / task?.progress / task?.live …
  ```
  断线由浏览器 `EventSource` 自动重连；不支持时 `connected=false`，调用方可回退轮询。

### ⚠️ 为什么没直接把 13 处轮询改掉
`ProjectWorkbenchPage.tsx`（**6161 行**）里有 13 处 `setInterval`（`:118,395,677,1078,3619,4019,4231,5085…`），且该文件**正在被实时编辑**。把它们改成 SSE **必须**：① 走前端构建（`npm run build` → `app/static`）；② 做 UI 冒烟（进度不显示/重复渲染/断线重连都可能出问题）。**在没有前端构建与 UI 测试能力的条件下强改生产工作台，风险大于收益**，故本轮只交付「后端 + 可复用 hook」，迁移按下面步骤增量做。

### 迁移步骤（建议：一次一处，先建后测）
1. 改一处轮询：`useEffect(setInterval(...))` → `const { snapshot } = useEventStream();` + 用 `snapshot?.tasks.find(...)` 驱动同一份 state。
2. `cd frontend && npm run build`（产物 → `app/static`）。
3. 冒烟：起后端 → 开工作台 → 跑一个任务，确认进度推进、任务结束态正确、断网后自动恢复。
4. 建议优先迁移**任务进度**（`:3606-3640` `pollTask`，与 SSE 快照同源，最贴合），再迁 `:677` 全局状态、`:4019` 画布。

### 验证 / 回退
- 后端验证：`curl -N http://127.0.0.1:5211/api/events/stream`（应见到 `: connected` 与 `data:` 帧）。
- 回退：前端未迁移前，后端端点存在但无人调用，**零影响**；hook 是纯新增文件，删之即净。

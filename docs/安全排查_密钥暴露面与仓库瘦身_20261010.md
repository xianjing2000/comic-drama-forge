## 二、唯一需要处理的两处

### 1. GitHub fine-grained PAT（93 字符，前缀 github_pat_11CP6NHNI0…）

- **唯一落点**：DSH 会话记录 `%DSH_HOME%/sessions/session-aeeaeb34-…/session.v4.jsonl.zstd`，共 5 处；
  其中 3 处是用户消息「改成这个令牌试试…」，1 处是我的 reasoning，1 处是我当时把它
  写进了 `run_code` 的 code 参数（我自己的操作失误，记录在此）。
- **不在**任何仓库文件、git 历史、`.git/config`、reflog、远程 URL 或凭据管理器里。
- 本机 GitHub 认证实际走的是：远端 SSH（`id_ed25519_github_new`）+ gh CLI 的 `gho_` OAuth token。
  ⇒ **这枚 PAT 没有被任何自动化引用，直接 Revoke 零影响**。

处置（GitHub 网页端，3 步）：

1. Settings → Developer settings → Personal access tokens → Fine-grained tokens；
2. 找到该 token（创建时间约 2026-10-10，`11CP6NHNI0BJg8yJLIT2MC_` 开头）→ **Revoke**；
3. 若确实还需要一枚：新建后**不要再粘贴进对话**，用 `gh auth login --with-token` 或
   `git credential-manager store` 写入凭据管理器即可。

### 2. DeepSeek 平台 API Key ×4（AGNES / AGNES2 / AGNES3 等）

- **落点**：另一个会话 `session-e012220c-…`。是某份凭据文件的内容被读出/粘贴，形态为
  `refs:` 段下的 `AGNES*_API_KEY: sk-…`（4 个不同值，各 51 字符）。
- 工作区里**没有**这些 key 的明文（`ai_config.json` 只存 base_url / model，密钥走
  `output/secrets.enc` + 主密钥）。
- ⇒ 建议到 DeepSeek 平台**轮换这 4 枚 key**，并避免以整份文件粘贴的方式交流。

## 三、顺带发现的两处环境问题

1. **全局 `git config --global http.sslVerify = false`** —— 所有 HTTPS git 操作都不校验证书，
   等同放弃中间人防护（Git Credential Manager 的 TLS 告警就是它引起的）。
   已把**本仓库**显式设为 `true`，实测 `ls-remote` / `push` 均正常、告警消失。
   全局是否一并打开，建议由你决定（其它仓库若依赖 GH 加速代理可能另有原因）。
2. `git config --global http.version` 写成了 `http/1.1`（无效值，git 每次报警告），已改为 `HTTP/1.1`。

## 四、仓库瘦身：256.56 MB → 134.56 MB（-122 MB，-47.6%）

`git count-objects -vH` 前后对比：

| 指标 | 前 | 后 |
| --- | --- | --- |
| `.git` 目录总大小 | 256.56 MB | **134.56 MB** |
| size-pack | 247.56 MiB | **134.43 MiB** |
| 松散对象 | 519（8.53 MiB） | 0 |
| in-pack 对象数 | 5544 | 4597 |

**根因**（不是「历史里东西太多」，而是两处「撑着不删」的引用）：

- `refs/original/refs/heads/main` —— 早年 `git filter-branch` 的遗留引用，把重写前的整条历史
  钉住不放，其中独占 109.7 MB（`electron-app/electron-v33-official.zip` 一枚就占 109.70 MB，
  `.gitignore` 第 138 行虽已忽略它，但它仍活在旧对象里）。
- 822 条 reflog 条目 —— 让大量中间提交无法成为垃圾。

**做了什么**：

1. 先 `robocopy` 整份 `.git` 到 `%APPDATA%/mjscxt-desktop/_git_backup_20261010162124`（596 文件 / 256.56 MB）
   并导出全部 refs 的 SHA 清单；
2. `git update-ref -d refs/original/refs/heads/main`；
3. `git reflog expire --expire=now --all`；
4. `git gc --prune=now`。

**没做什么（有意）**：`refs/dsh-turn-rewind/v2/*` 的 **76 个 DSH 回退快照引用全部保留**，
验证 76/76 可解析、0 损坏。这些快照把工作区里的媒体文件也一并提交（`worktree/_配音试验/*.mp4`、
`head/review_tmp/*.png`），是剩余 134 MB 的主要构成 —— 但它们同时也是「回退到某一轮」的能力，
删不删属于产品取舍，**不由我代为决定**。

验证：`git fsck` 退出码 0；HEAD 仍是 `e54a018`；`git status` 干净；93 个待推提交已全部推上远端。

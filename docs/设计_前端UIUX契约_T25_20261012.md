## 3. 状态规范（五态，本任务重点）

### 3.1 五态定义（判据 → 视觉 → 必须给出的下一步动作）

| 态 | 判据（可判定） | 视觉 | 必须给出的动作（MUST） | 组件 |
|---|---|---|---|---|
| **空 Empty** | 请求成功 且 集合为空（≠ 未请求 ≠ 请求失败） | 图标 + 标题 + 一句话说明 | **≥1 个可执行动作**（新建/生成/去上游/刷新）+ 解释「为何是空的」 | EmptyState（action 必填） |
| **加载 Loading** | 首次请求在途且无旧数据 | 与真实版式同形的 Skeleton（禁止整页居中转圈） | 无；但 >30s 出现「已等待 Ns」+「查看日志」 | Skeleton / Loading |
| **错误 Error** | 请求失败或 success=false | 分级见 §3.2 | **恢复动作**（重试/去配置/去日志）+ 错误码 + 可复制 | ErrorState / InlineBanner |
| **部分成功 Partial** | 有产物 且 存在失败/缺失/跳过单元（incomplete_shots / missing / skipped / failed>0） | 内容正常展示 + warning 条 + 计数 | 「已完成 N/M」+「缺哪些（可定位）」+「只重做缺失单元」 | PartialBanner（新）+ StateBadge(attention) |
| **过期 Stale** | 上游输入变更，既有产物不再对应当前输入（meta.stale） | warning 条/药丸 + 影响范围 | 「重新渲染该步」+「仍然使用（记录差异）」 | StaleBanner（新，或 PartialBanner tone=stale） |

**选择决策树（实施时照此判定）**

    请求失败？ ─ 是 ─ 还有旧内容？ ─ 有 ─ InlineBanner(danger)
                                  └ 无 ─ ErrorState（硬失败）
              └ 否 ─ 结果为空？ ─ 是 ─ EmptyState（action 必填）
                              └ 否 ─ 全部单元成功？ ─ 是 ─ 正常展示（StateBadge done）
                                                  └ 否 ─ 输入变了？ ─ 是 ─ StaleBanner
                                                                    └ 否 ─ PartialBanner

## 6. 交付与验证方式

### 6.1 生产期安全构建流程（避开 emptyOutDir 清空生产目录）

**为什么危险**：frontend/vite.config.ts:50-56 = outDir '../app/static' + **emptyOutDir: true**；frontend/package.json:7 的 npm run build = tsc && vite build → 直接执行会清空正在被后端服务的 app/static（窗口期内所有页面 404；桌面版还可能因资源指纹变化触发重播种）。

**安全流程（在最后一步之前完全不触碰 app/static）**：

    # 0) 类型检查（不写任何文件）
    cd frontend ; npm run type-check          # tsc --noEmit

    # 1) 构建到 staging：CLI --outDir 覆盖配置，emptyOutDir 只作用于 staging
    npx vite build --outDir ../.build-static-stage-<ts> --emptyOutDir
    #    ⚠️ 禁止执行 npm run build（它会走配置里的 ../app/static）

    # 2) 校验 staging 完整性
    #    - index.html 存在且引用 /assets/index-<hash>.js
    #    - assets/index-*.js|css 存在（与 electron-app/main.js:409-413 的指纹规则一致）
    #    - 资源数量与上次构建同量级（突降 = 构建失败）

    # 3) 备份 + 原子替换（同盘 rename）：只替换 index.html / favicon.svg / 新增的 assets/index-*.js|css
    #    ⚠️ 不删除旧 hash 产物 —— 已打开的页面仍会请求旧文件名

    # 4) 回退：把备份的 index.html 写回即可（旧 hash 资源仍在，天然可回退）

**关键设计点**
- 静态资源是**内容哈希命名**（Vite 默认；main.js:409 明确按 index-*.js|css 取名）→ 「增量覆盖 + 只替换 index.html」既安全又可回退。
- Flask 侧用 send_from_directory（app/app.py:678/684/696/1071；app/asset_refs.py:82-110），**无需重启后端**即生效；桌面版需资源增量/重播种把安装区 static 更新（electron-app/main.js:341-352、:384-414）。

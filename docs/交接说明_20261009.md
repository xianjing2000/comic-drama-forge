## 5. 本会话固化的规程（踩坑换来的）

1. `routes/_shared.py` **不得** import 任何 `routes.*`（共享层必须是最底层）；
2. 搬代码不要用 `current_app.logger`（用 `_app_logger()`）；
3. 带 `route(` 装饰器的节点**不得**当助手搬走（用惰性转发器）；
4. **写 TS 模板串时不要放反引号**（会截断模板串，本会话踩了 3 次）；
5. **改任何守卫前先 `grep "def check" <守卫>`** 确认参数顺序（三种签名并存，踩了 3 次）；
6. **grep 结论先按非备份路径过滤**（.bak 会淹没有效结果，误判过一次）；
7. 源码类断言的**窗口切片**是隐性耦合：函数变长会把目标挤出窗口 → 尽量锁不变式而非计数；
8. 守卫改动必须**留 .bak 快照**；产品改动必须**同步三处副本**（安装区 / 运行镜像 / 打包输入）；
9. 每域搬迁走**五步放行**：导入自检 → 路由完整性 → 端点冒烟 → 行为冒烟 --diff → 全量巡检零新增红灯；
10. 修为真 bug 后**立刻确认副作用面**（本会话修好一条此前必崩的分支后，它第一次真的写盘，
    差点把测试数据写进真实 output/ —— 已清理并修正守卫隔离）。

## 附录：如何正确重启后端（2026-10-09 实测）

运行实例 = Electron「漫剧工坊」拉起的 `python.exe serve.py`（父进程是漫剧工坊）。
改完 app/ 下的代码**必须重启它**才生效。**手动启动时必须带 Electron 注入的两个环境变量**：

    $env:APP_PORT='5211'                                            # 少它 → 起在默认 5210，前端连不上
    $env:MJSCXT_DATA_DIR="$env:APPDATA\mjscxt-desktop\mjscxt-data"    # 少它 → /api/projects 空（像项目丢了）
    Start-Process -FilePath C:\mjscxt_p139\resources\python\python.exe `
      -ArgumentList serve.py `
      -WorkingDirectory "$env:APPDATA\mjscxt-desktop\resource-mirror\app" -WindowStyle Hidden

改动是否已生效的判据：**后端进程启动时间 晚于 镜像文件 mtime**。

    2026-10-09 实况：旧 pid 29212 启动 09:44:09 < 文件 14:02:01（旧代码）
                     新 pid 1924  启动 14:40:47 > 文件 14:02:01（新代码，已生效）

## 一、上线阻断项（实锤缺陷，建议修完再上）

1. **集号正则失效** `app/app.py:16354`：`re.match(r"^ep(\\d+)$", d)` 在 raw 字符串里 `\\d` 是「字面反斜杠+d」，`ep02` 等目录永远匹配不上 → 第 2 集起从视频目录派生的集号全部丢失（退化为「有 mp4 就算第 1 集」）。改成 `r"^ep(\d+)$"`。
2. **项目配置相对路径读取** `app/app.py:6111-6116`、`6155-6157`：`os.path.join(_safe_project(name), 'config.json')` 拼出的是相对 CWD 的路径（`_safe_project` 返回项目键，不是绝对路径）→ 风格参考图 / 世界观注入静默读不到（异常被吞成 debug 日志）。
3. **质检链可整体 fail-open** `app/qc_client.py:2179-2233`：`blocking_spec` 文字规格模式下仍无条件 `image_paths.append(blocking_ref)`；调用方只传文字规格不传图时，空路径 `open()` 抛 FileNotFoundError → `interface_fault=True` → 上层按「接口故障」放行未质检图片。同根问题：`build_blocking_note`（`qc_client.py:268-296`）文案仍按「第 2 张=3D 基准图」数图，文字规格模式下没有第 2 张图，设定图实际从第 2 张开始，送模型的图序说明整体错位一格。
4. **台词语径四处打架**：config `SHOT_SPEECH_BUDGET_CHARS=16`（config.py:362）vs novel_to_script 提示词「上限 20 字」（novel_to_script.py:453）vs qc_client 剧本质检「30 字（约 6.7 秒）」（qc_client.py:706，旧换算）vs prompt_qc `_AUDIO_MAX_CHARS=60`（prompt_qc.py:248）。时长已做 config 占位符同源（qc_client.py:3878-3882），台词没有——30 字/6.7 秒是已废弃口径，会直接诱导质检误判与模型超写。
5. **超分默认剥音轨** `app/upscale_client.py:578`：`attach_audio` 默认 False，TE 引擎仅在 `attach_audio and has_audio` 时保留音轨（upscale_client.py:404-407）→ 与「成片即带配音（H3_EMIT_AUDIO=True）」新口径冲突。需核实 pipeline 超分后是否回填音轨；若否，全链成片静音。
6. **备份文件混入拼接** `app/video_postprocess.py:246 vs 116`：剥离音轨的备份名 `shot_NN.withaudio.bak.mp4` 命中 `_SHOT_RE` 且不以 `_full.mp4` 结尾 → 会进拼接清单；且按字典序排在原片**前面**（同一镜出现两次、含音轨版在前）。
7. **autonomous 状态恒 0** `app/autonomous.py:268-270`：读 `progress["stats"]["done"]`，而 `autopilot.project_progress`（autopilot.py:645-655）顶层是 `total/done/percent/episodes`，无 `stats` 键 → `/api/autonomous/status` 的 episodes_done/pending/failed 永远是 0。同型：`generate_report` 重试数恒 0（autonomous.py:347，history 行无 `retries` 键）。
8. **coverage 阈值 fallback 漂移** `app/coverage.py:44`：文档（:22）说默认 0.70，实现 fallback 仍是 0.95——`novel_to_script.COVERAGE_THRESHOLD` 一旦改名/缺失，阈值静默回到已废弃的 0.95。另 `rounds_cap`（coverage.py:565-566）把 `max_rounds=0`（想关）改写成 1，「0=关」语义不成立。
9. **半截剧本判成功** `app/app.py:12882`（`_salvage_episode_script`）：分集任务报错后「以产物为准按成功回填」，产物 >120 字节且有 shots 即判成功（degraded=True）——可能把残次剧本上报为成功并流入下游。
10. **拼接清单/导出 ID 稳定性**：`video_postprocess.py:450` concat 清单单引号不转义（同文件 606 行 SRT 却转义了，口径不一）；`nle_export.py:206` 剪映素材 ID 用内置 `hash()`，受 PYTHONHASHSEED 影响跨进程不稳定（应换 hashlib）。

## 二、两段式架构的三处实质缺口（2026-10-04 拍板 vs 代码现状）

1. **人审无状态落盘，「文件存在=已过审」**：【已关闭】2026-10-05 起文学剧本无需人工审核，`use_screenplay` 的语义改为「直接使用文学剧本改写分镜」，不再检查审核状态。相关审核字段/分支已删除（如 `state["approved"]`、`approved_at`、`review_status` 等）。 
2. **托管流水线没有接两段式**：【已完成】2026-10-05 托管链路 `autopilot._produce` 与 `run-once` 在调用 `pipeline.run_episode` 前已注入 `config.screenplay_text`（`novel_screenplay.load_screenplay(project_key, episode_no)`），文件存在即以文学剧本改写分镜，无需人审。未改动 pipeline 签名，完全复用手动路由逻辑（`continuity.convert_chapter_with_continuity` 的 `screenplay_text` 参数）。
3. **coverage/script_consistency 的「原文」错位**：【已完成】2026-10-05 `continuity.convert_chapter_with_continuity` 新增 `screenplay_text` 参数，内部计算 `ref_text = screenplay_text or seg`，传给 `coverage.run_coverage_check` 与 `script_consistency.run_script_consistency_check`。剧本生成仍以原著为基准，质检初筛保留原著，二筛（覆盖率/一致性）基准已切换为文学剧本改写稿。为空时自动回退原著（fail-open）。

> 结论：手动链路已打通（use_screenplay→文学剧本→改写→按场次生成→only_scenes/build_only 均真实接线）；托管链路已接入（autopilot._produce / run-once 注入 config.screenplay_text），coverage 与 script_consistency 基准已切换为文学剧本改写稿（ref_text），两段式全链路在代码层面已闭环。

## 五、其他风险（提示级）

1. **复核可洗白硬闸**：qc_client `_recheck_image_verdict`（2069-2118）对「首检命中 CRITICAL 关键词、复检未命中」以 second.accepted=True 放行——关键词硬闸退化为两次采样投票（客观层 fatal 有跳过复核保护，AI 层没有）。

5. **整集 concat 清单固定名** `_concat_epNN.txt`（app.py:8829）——同集并发重跑互踩。
6. **裸 `int(request.args)` 500**：app.py:17614/17630/17771/17418。
7. **`/api/ai/config/reveal` 明文回显密钥**（app.py:10266）——本地单用户理由成立，但部署若绑非回环地址即是敏感面（host_guard 有兜底）。
8. **i18n 缺口**：UpdateChecker/ShotPromptEditor 硬编码中文不走 t()；en-US 包未同步新键会露键名。
9. **assert 守卫被 -O 剥离**：h3_director_builder:142-148 用模块级 assert 守卫节点参数表。

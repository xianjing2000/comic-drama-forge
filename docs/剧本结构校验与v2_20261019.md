## 二、系统级问题（不是这份剧本的锅）

### 1. `tail_shot_indexes` 实现与文档相反 —— **已修**
文档写「按连续 run 分组，不能按 scene_no 值分组」，实现却是按 `scene_no` 的**数值**比较。
后果：手写/旧剧本没有 `scene_no`（全为 0）时，**只把整集最后一镜**当收尾镜 —— 每场戏的
收尾镜享受不到「可短于 10 秒」的例外（v2 的镜 10 因此被 QC 判「时长过短」）。
现改为 `key = (location, scene_no)` 的**连续 run** 分组，三处消费点（时长 clamp / QC 判据 /
分镜单帧降级）同时受益。实测：无 `scene_no` 的两场剧本 → 尾镜 `{9, 11}`（镜 10、镜 12）。

## 三、这轮落地了什么

### 1. `app/script_structure.py` —— 确定性校验器（不调模型）
- `check(script)` → `{ok, p0, p1, info, stats, bible}`：
  空镜开场 / 钩子太晚 / `dialogue` 字符串 / 台词缺 speaker / 字段缺失 / `beat` 越界 /
  bible 未知名 / **道具定义了从未入镜** / **外观特征不在 bible**（同义词组判定，避免
  「伤痕 vs 浅疤」误报）/ `items_state` 键不在 `items_in_shot` / 动作链断裂 /
  裸英文 `prompt_h3` / 场景缺 `int_ext/time_of_day`。
- **时长节奏只在项目允许弹性时长时才检查**（`SHOT_DURATION_MIN != SHOT_DURATION_MAX`），
  否则每个合规剧本都会被判「节奏平板」——这是刻意的不误报。
- `bible_coverage_verdict(script)`：bible↔镜头摘要，已接进 `quality_stage.acceptance_verdict`
  的 `script_bible` 字段（每份验收报告都能看到道具是否入镜、有没有外观漂移）。

### 2. 接进流水线
`pipeline.step_script` 在剧本落盘前跑一次：结果写进步骤 `detail.structure_check`（界面可见）
+ 日志。**默认只记录不阻断**；`MJSCXT_SCRIPT_STRUCT_GATE=block` 时 P0 直接判该步失败。

### 3. 提示词补规则（`app/prompts/script_generate.txt`）
- **③-开 开场三连**：镜1 反常画面+冲突（禁止空镜建立）、镜2 点名与指控、镜3 升级并交代
  「为什么被看不起 / 想要什么」；
- **③-因 爽点必须先有因**：压迫事由、处境与渴望、触发条件三件套，禁止「上一镜被骂、下一镜无敌」，
  禁止台词提到前文没发生的事；
- **⑪ 非角色台词不得进 `dialogue`**（系统提示/旁白/画外音 → `audio_cues` 或专用角色）；
- **⑫ 群像/群嘲台词必须有说话人**（先定义群演角色，否则音色失效、群众脸不一致）。

### 4. `tools/script_schema_upgrade.py` —— 旧格式机械迁移（不编内容）
字符串 dialogue → 数组（**只在恰好 1 个出场角色时**确定 speaker）、补齐标准字段、
`beat` 归四值、场景补 `int_ext/time_of_day`、重算统计；推断不了的**如实列出**。
带「非角色台词守卫」：`【】`/「叮」/「系统」/「画外音」不会被归给场上角色。
迁移后自动跑一遍结构校验。`--in-place` 会先备份。

## 五、同类问题四连修（2026-10-19 追加）

### 1. `visual_detail` 上限统一
同一文件两处上限（硬指标「≤30 字」vs schema「≤120 字」）→ 统一为
**schema 权威：≤120 字（建议 ≤30 字）**，硬指标段同步写「建议 ≤30（硬上限 120）」。

### 2. `description` 长度口径对齐
QC 侧早已「不按字数判缺陷、只留 <10 字兜底」，生成侧却还写着「下限100上限120」→
schema 改为 **「100~120 字为宜（不设硬上限）」**，硬指标 ② 同步；「超 120 回头查」保留，
但明确**判据是内容、不是字数**。

### 3. 两套结构校验器合并（消除双轨）
`qc_client._validate_script_structure` 在原有字段检查后**并入 `script_structure.check()` 的 P0**
（issues 在 `check_script` 里属 critical）。只并 P0：P1 是建议项，不该把整本判失败。
实测：v1 在界面 QC 里现在同样报 2 条 P0（旧格式 dialogue / 空镜开场），v2 为 0 —— 与流水线一致。

### 4. **P0 运行层事故：登记表把「每镜 10 秒」改回了 5/8 秒**
- `config_doctor.REGISTRY` 的 `shot_duration_min/max/granularity_target` 默认仍停在
  **5.0 / 8.0 / 5.5**；而 `config_center.apply_to_runtime()` 在**启动时**会把 REGISTRY 解析值
  **setattr 回 config 常量**。
- VM 实测：`apply` 前 `MIN=10.0 MAX=10.0`，`apply` 后变成 **`5.0 / 8.0`** ——
  2026-10-14 定稿的「每镜固定 10 秒」**在运行时从未生效**（config.py 写 10，进程里是 5/8）。
- 修复：① 三个默认值改 **10.0 / 10.0 / 10.0** 并同步说明；
  ② `config_center` 新增 `_migrate_known_defaults()`：DB 里若仍是**旧默认值**
  （精确等于 5.0/8.0/5.5，说明用户从未改过），启动时自动升级为 10 并写 note；自定义值不动。
  实测：写入 5.0/8.0 → apply 后 DB 与生效值均为 10.0/10.0。
- 影响面：时长 clamp、QC 时长判据、收尾镜例外、分镜九宫格降级。

### 低危两条（确认不改）
- `CAPTION_MAX_CHARS=200` 只是**告警阈值**（`_norm_caption` 按用户要求已不截断）；
  schema 的「≤20 字」是写作指引，不是硬校验，不构成功能冲突。
- 27+ 镜时送质检 AI 的副本会把 `description` 压到 ≥80 字：**只影响送检副本，不影响落盘剧本**，
  且已带「无截断」note，属必要 token 预算。

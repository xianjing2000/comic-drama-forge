## 1. 一集的生产链路（7 步）

```
script → tts_pre → assets → storyboard → video → upscale → final
 剧本     参考音色    图片资产    分镜图       视频       超分      成片
```

- 口径：**一章 = 一集**，示例集 46 镜 / 8 场 / 成片约 176.5s
- 重试策略（`pipeline.py:3027`）：`step_max_retries=2`，且 `GATED_STEPS=(script, storyboard, video)` 保底 1 次
  → **这三步最多会各跑 3 遍**
- ⚠️ 重试粒度是**整步**，不是单元级：script 崩一次 = 整个剧本阶段（含覆盖率校验、多轮连贯性重写、一致性校验）全部重跑

## 3. 问题分级与证据

### P0｜必崩缺陷：正在杀死生产（可静态检出）

用 `pyflakes` 扫全项目，`undefined name` 共 8 处。**这不是风格问题，每命中一次就是「整步白跑 + 重试」**：

| ① | `app/continuity.py:2631, 2636` | `novel_to_script` | **剧本阶段跑完 90% 后崩 → 整步重试（最多 3 遍）** | 🔴 **正在发生** |
| ② | `app/video_helpers.py:1599, 1603` | `time` | 视频提示词预热 100% 失效 → 视频阶段 GPU 干等 LLM | 🔴 活跃 |
| ③ | `app/video_helpers.py:628` | `autopilot` | style 为空时崩（视频提示词构建主链路） | 🟡 条件触发 |
| ④ | `app/video_helpers.py:2416` | `_rs_ep` | 跨集末帧缓存失败（被 except 吞） | 🟡 降级 |
| ⑤ | `app/workers/audio.py:173` | `_record_preflight_lesson` | 配音教训沉淀失败（被 except 吞） | 🟡 降级 |

**① 的根因（已核实到行）**：

对照其他文件都写对了（`pipeline.py` 用 `A.novel_to_script.xxx`、`video_helpers.py:95` 用 `from novel_to_script import ...`）——
**只有 continuity.py 这一处是坏的**，是 t7（10-12）「落盘前补场次编号」根修时引入的回归。

**实证（本次日志，就在此刻）**：

### P1｜结构性浪费（配置可解，零/低质量代价）

### P2｜硬件与资源天花板

- **8 GB 显存 + 33 GB 内存**，要装 H3 19.53 GB + 文本编码器 14.61 GB
- 实测内存耗尽窗口：**86 分钟才出 1 镜**（正常 3～6 分钟/镜）；ComfyUI private 峰值 23.7 GB，系统 Commit 峰值 49.6 GB > 物理内存
- GPU 健康态 84～112 W；换页瞬间掉到 **24.8 W**（util 85% 但 GPU 空转等数据）
- `TASK_QUEUE_CONCURRENCY=1` 是**正确**设置（单卡调大只会加剧显存换入换出）
- 另有 2 处工程摩擦：`upscale_client.DEFAULT_CHUNK_SECONDS` 等 4 个常量未登记配置体检；分析统计 `output/analytics/events.jsonl` 只有 pipeline 级事件，**缺阶段级耗时**（导致每次都靠人工拉日志）

## 4. 减时清单（按 ROI 排序）

### 第 1 优先｜零成本、收益最大（建议立刻做）

1. **修 `continuity.py` 的 NameError**（①②合并 1 处）
   ```python
   # 方案 A（推荐，与其他文件口径一致）
   from novel_to_script import (..., normalize_scene_numbering, collect_scene_flow)
   # 并把 2631/2636 行的 novel_to_script. 前缀去掉
   ```
   → 剧本阶段不再白跑。**按当前日志，每次省下整段剧本时间（实测一次 ≈ 9～10 分钟，且它重试 3 遍）**

2. **修 `video_helpers.py:1599/1603` 的 `time`**（函数内加 `import time`）
   → 视频提示词预热恢复，视频阶段不再 GPU 干等 LLM

3. **补 `video_helpers.py:628` 的 `autopilot`**（改 `A.autopilot` 或顶部 import）

4. **加一道防回归门禁**：把 `pyflakes` 的 `undefined name` 纳入提交/CI 检查
   → 这类缺陷是**零收益、全损耗**，且能被静态检出，不该靠线上日志发现

### 第 2 优先｜改配置（分钟级，可能省 1～3 小时/集）

5. `PROMPT_ENHANCE_TIMEOUT_SEC: 90 → 25`
6. 只关 **storyboard** 的提示词增强（资产/尾帧/H3 保留）
7. 3D 站位图：`_FIRST_RENDER_TIMEOUT: 120 → 30`，并**去掉重试**
8. 收紧质检重试预算（「面板雷同」不应触发完整重出图）
9. 8G 机器**保持 `enable_upscale=false`**（现在是对的）

### 第 3 优先｜架构（能显著改善"反复重来"）

10. **单元级续跑**：把重试粒度从「整步」下沉到「镜/场/段」。现在 script 崩一次全部作废，video 失败整集重来
11. **内存护栏**：可用内存 < 8 GB 预警、< 6 GB 暂停非必要前置段，避免 86 分钟/镜的全线停摆
12. **视频段级返工**：结合 T9 已落地的段级素材，失败只重跑坏段（当前是整集重来）
13. **补阶段级耗时埋点**：events.jsonl 现在只有 pipeline 级，阶段级耗时全靠读日志

### 第 4 优先｜硬件

14. **内存加到 64 GB**（最直接；当前 33 GB 装不下 19.5+14.6 GB 两级搬运）
15. 换 ≥24 GB 显存（可开 `--normalvram`，消除 RAM↔VRAM 搬运抖动）

## 5. 一句话总结

> 这一集跑不完，主因**不是模型慢，而是剧本阶段最后一行代码把一个已经算完的剧本扔了**；
> 其次是分镜前置段里 56 秒/镜的"付费但不生效"的提示词增强、和"必然超时再降级"的 3D 站位图。
> **先修 1 行必崩缺陷 + 3 项零代价配置**，收益远大于任何硬件投入。

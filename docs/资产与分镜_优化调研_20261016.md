> 方法：联网调研同类做法 + 本仓只读核验现状（缺陷带 `文件:行号`）。**本文件不含代码改动**（除注明的一项已落）。
> 配套：`docs/配音与角色生成_缺陷与借鉴_20261016.md`（配音 + 角色一致性的同类借鉴与缺陷）。

## 0. 一句话结论

四环节的**共性根因**是「**一致性只靠文本锁，缺画面级手段**」：角色靠逐角色单图+文字锁、道具靠一张固定 base.png（还会**主动对抗**剧情状态变化）、场景的**下游实际产物（grid）没传参考图**、分镜的单帧模式**既无构图多样性约束、质检还被谎报成九宫格**。**最高 ROI 不是上大模型，而是修好几处「结构性自相矛盾」**（下面 Top-8 的 1/2/7）。

## 5. 最值得优先做（Top 8，跨四环节）
1. **修 HD 增强的三等分错切**（`asset_enhance.py:173`）——波及所有档位、产物又是分镜首选身份锚点。**ROI 最高 / 风险最低**。
2. **修质检把单帧分镜谎报为 3×3 九宫格**（`qc_client.py:2405`）——✅ **已修**（见 §6）。
3. **道具状态模型 `item_states` + 状态变体参考图**（`continuity.py:1916-1930`）——治「剑断了仍喂完好剑」的结构性冲突。
4. **场景 `grid.png` 出图补 `ref_images` + 引入 qwenmultiangle 式按机位派生**（`asset_worker.py:1244-1249`）——下游实际用 grid，目前空间对齐被旁路。
5. **跨镜连续性锚点保底**：上一镜锚点不因 cap 被丢（`storyboard_helpers.py:2311`）、单镜重跑补锚点（`331-333`）。
6. **单帧分镜构图多样性约束**：复活「相邻镜禁同景别硬切」到单帧（生成端+质检端，零新增依赖）。
7. **参考图「整图不裁剪」口径统一**（`storyboard_helpers.py:1296-1341`）——与项目硬口径冲突、劣化身份锚点。
8. **道具产权 + 复用**：owner 驱动出图、主人形象链路修（或明确单人物裁切）、道具纳入 `asset_library` 指纹。

**可选实验项（受 8GB 约束，需实测）**：身份注入 PuLID-FLUX / DreamO `--nunchaku --offload` / CharaConsist `init_mode=3`——角色一致性最大杠杆，但 8GB 风险高，**先在单角色镜试点**。

## 6. 本轮已落地的修复（1 项，已 `py_compile`/`pyflakes` 通过）
- **质检「九宫格谎言」**：`check_image` 增加 `is_grid: bool = False` 参数，`STORYBOARD_GRID_ANALYSIS_NOTE` **仅在 `is_grid=True` 时追加**（`app/qc_client.py:2405` 一带）；场景九宫格质检调用点补 `is_grid=True`（`app/asset_worker.py:1273`）。
  - 效果：单帧分镜不再被质检模型当成 3×3 九宫格（消除臆造的「面板雷同 / 只看 1~2 格」误判）；场景 grid 仍保留逐格分析。
  - ⚠️ **改的是 `app/` 代码 → 需同步四副本 + 重启**（`python tools/sync_copies.py --apply`）。

## 7. 需要你拍板的决策点
1. **HD 增强（Top-1）**：对非「正/侧/背」档位**关 HD、退回整图**，还是**按实际版式重写切分**？（前者简单安全）
2. **道具状态（Top-3）**：是否引入 `item_states` + 按状态取参考图变体？
3. **场景机位（Top-4）**：是否评估 **qwenmultiangle LoRA**（Qwen 系同源）做按机位派生？先做「给 grid 补 ref_images」这条低成本的？
4. **一致性大杠杆（可选实验）**：是否在**单角色镜试点** PuLID/DreamO/CharaConsist（8GB 需实测）？
5. **落地节奏**：先批量落 **Top-1 / 5 / 7 / 8**（低风险、止损类），还是先做 **Top-3/4**（结构性、收益大改面也大）？

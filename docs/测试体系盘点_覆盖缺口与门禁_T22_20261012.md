## 3. 测试策略：分层与门禁

### 3.1 分层（哪些走单元、哪些必须真环境、哪些只能人工目检）

| 层 | 判据 | 允许依赖 | 本层该测什么 | 时长预算 |
|---|---|---|---|---|
| **L1 单元** | 纯函数 / 纯数据结构，输入 → 输出确定 | 无（连文件系统都不要） | 排序键、词表判定、正则、分流判定（mock 掉 subprocess） | < 1s |
| **L2 契约（静态）** | 「两处必须一致」「签名/调用点形状」这类**结构性**不变量 | 只**读**源码文本（AST） | 调用点参数完整性、双表同源、prompt 双份拷贝一致、路由完整性 | < 1s |
| **L3 集成（假外部）** | 真文件系统 + 假外部进程（mock subprocess / concat_videos） | 临时目录 | 重拼闭环、stale 状态机、写盘/读回 | < 2s |
| **L4 集成（真外部）** | 必须真 ffmpeg / 真 ffprobe 才能暴露的缺陷（音轨、时长、流） | ffmpeg + 临时目录 | concat 音轨一致性、静音轨补齐、-an 取舍 | < 30s |
| **L5 人工目检**（**不可自动化**） | 画质类结论 | — | 分镜雷同、手指畸变、角色换脸、画面崩坏、音色像不像 | — |

**L5 边界的强制纪律（本轮 5 个缺陷里 2 个属于此列）**：

- 「软放行漏判」这类**判据同步**问题，LLM 判官的结论不可复现，但**判据表与判定函数完全可测**
  → 把它们下沉成 L1/L2 是唯一正确解法（t22 已做）；不要让「不可复现的模型输出」成为不写测试的借口。
- 「手指畸变 / 面板雷同」的**最终判定**仍是人工（VLM 结论），但代码侧必须保证：**VLM 一旦说了，两个闸门都不会放过**。
  这就是 L1 断言「生产原文必须两侧都判缺陷」的价值。

### 3.2 必须真 ffmpeg 的部分（不能 mock）

只能 mock 掉「分流判定」，不能 mock 掉「ffmpeg 真的怎么拼」。理由（t22 实测）：

- 音轨截断缺陷**只在真实 ffmpeg 行为里出现**：容器时长取最长流 → 4.023s 看着正常，音轨其实只有 2.06s。
- -shortest / anullsrc / aformat=channel_layouts=mono 的组合是否真能对齐，只有真跑才知道。
  （test_concat_audio_mutation.py 就是**故意真跑两次**：一次当前实现、一次内存里的旧实现，实测 2.06s vs 4.02s。）
- 缺 ffmpeg 时测试**必须 skip 并显式声明「不算通过」**，绝不能因为跑不了就当作绿。

### 3.5 测试自证：为什么必须做「变异验证」

t22 新增的测试针对的是**已经修好**的缺陷 —— 跑绿只证明「当前代码没问题」，**不能**证明「测试能拦住它」。
tests/test_mutation_guards.py + tests/test_concat_audio_mutation.py 用**运行时变异**补上这份证据：

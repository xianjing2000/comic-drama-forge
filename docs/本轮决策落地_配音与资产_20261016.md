## B. 每个角色音色必须不同 —— 待做
**根因**：① 预置池很小（`tts_client.MALE_POOL`≈5 / `FEMALE_POOL`≈4），`_assign_pool_speakers` **按名排序取模**（`tts_client.py:463-482`）、`_fallback_speaker` 同名哈希（`voice_bank.py:282-300`）→ 男 >5 / 女 >4**必然撞音色**；② H3 侧音频参考槽**硬上限 3**（`asset_refs.py:915`）→ 第 4 人起**完全没有** ref，音色不可控。
**设计**：① 预置池**扩容**；② 全项目**统一分配**（不取模静默复用，撞池即报「音色耗尽」并改用 **design + 唯一 instruct** 补位）；③ design 模式给每个角色生成**互不相同**的人设 instruct（现在无 voice_style 的角色会退 preset 撞池）；④ H3 侧对「本集有音色角色 >3」**显式告警**（现在静默丢弃），或按集拆分。
**目标**：`tts_client.py:67-68,463-482`、`voice_bank.py:282-300`、`asset_refs.py:811-949`。

## C. 前端「试听」 —— 待做（前端）
**根因**：`AudioTab.tsx:688` `disabled={busy || !cloneOk}` —— **`cloneOk`（ComfyUI 是否有克隆节点）为假时，所有行的「试听」都被禁用**；而 design/preset 模式的试听**根本不需要克隆节点**（只有「用户上传音色走 clone」才需要）。用户会误以为「只有群像不能试听」。另外未绑定行只显示「上传」（`:697-704`），群像若合成失败就没有试听按钮。
**设计**：① 「试听」只对 **clone 模式**的行 gate `cloneOk`（design/preset 恒可试听）；② 缺克隆节点时给**全局醒目提示**（写清「H3 参考音色依赖 ComfyUI 克隆/设计节点」）；③ 群像行提示「群像·群体音色」。
**目标**：`frontend/src/components/AudioTab.tsx:522-704`；`app/routes/tts.py:155-250`（后端已可读 502，保留）。

## D. HD 增强「按实际版式」重写切分 —— 待做（含一个**关键事实纠正**）
**关键事实**：角色四档版式 —— `primary`=**四区不对称**（正/侧/背 + 面部特写 + 配色板）；`supporting`=**双格**（正面+侧面）；`minor`=单图；`crowd`=合影。**四区版式代码自陈「无法做行列投影切分」**（`comfyui_client.py:1545`）。
**所以「按实际版式重写切分」的正确落法**：
- **不能**把四区/双格/单图/合影都按 1×3 硬切（现状 `asset_enhance.py:173` 的错误）。
- `supporting`（双格）→ 切 **2×1**（front、side）。
- `primary / minor / crowd` → **不切**，改为 **HD 整图**（`hd/base.png`，整图放大重绘）。
- `qc_helpers.prefer_hd_char_ref`（`:273-288`）相应：优先 `hd/base.png`（整图），`supporting` 才优先 `hd/front|side`。
**目标**：`app/asset_enhance.py:enhance_character_sheet`（+`CHARACTER_HD_VIEWS`）、`app/qc_helpers.py:273-288`、调用点 `app/asset_worker.py:1700`。

## §E 道具状态（后半已落地，2026-10-16）

**四段链路**（每段都留了 fail-open 回落，老剧本/无状态时行为与改动前**完全一致**）：

1. **状态契约**（已有）：`continuity.STATE_SCHEMA_HINT` 的 state_in/state_out 各含 `item_states`。
2. **剧本声明每镜状态**（新增）：
   - `app/prompts/script_generate.txt` 的 shot JSON 结构加 `items_state`（**默认 `{}`**，仅当本镜该道具与设定图状态不同才填）。
   - `app/novel_to_script.py`：`SHOT_FIELDS_DEFAULT` 加 `"items_state": {}`；新增 `_match_item_state(raw, items)` 把键**收敛到 bible 物品名**（模糊命中口径同 `_match_known_names`）、值截 20 字、未命中记 warning 并丢弃；`build` 处的 row 白名单（手工列举）显式保留该字段。
3. **变体出图**（新增）：`app/asset_worker.generate_item_state_variant(project, item, state)` —— 以该道具 base 图为参考走**图片编辑**（`generate_storyboard` img2img），落 `items/<项目>/<道具>/states/<slug>.png` + 同名 `.json` sidecar（存状态文案）。
   - 路由：`POST /api/assets/item/state-variant`（异步任务，进度走 `/api/generation/status/<task_id>`，`overwrite` 语义同服装变体）；`GET /api/assets/item/state-variants?project_name=&item=`（列已生成状态）。
4. **按 state 取图**（新增）：`app/asset_refs.state_slug/ item_state_image(item_dir, state, base)` —— 有 `<states>/<slug>.png` 取变体、否则回落 base；接入 **3 处**：
   - `qc_helpers._allocate_storyboard_refs` 的**生成侧**道具取图（普通道具槽 + 文字道具 image1 主体）；
   - `qc_helpers._qc_ref_images` 的**质检锚点**（判官必须拿同状态锚点，否则会把「剑已断」误判成「与设定图不符」——与既有「送检锚点必须与生成侧同源」纪律一致）。

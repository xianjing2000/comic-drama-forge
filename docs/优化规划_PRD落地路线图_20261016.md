## 0. 一句话结论

项目**不是一个待做大修的半成品，而是一条已经跑通、正在被维护的生产线**——真正的工作是三件事：**（1）先把「改一份漏三份」的多副本漂移这个地基堵死；（2）补齐返工闭环这个被用户点名的 P0 缺口；（3）把「数小时一集」的算子按 ROI 拆解提速**。PRD 里相当一部分「缺口」其实已被后修（见 §1），而相当一部分「✅ 已实现」的表述与默认运行路径相反——所以**动手前必须先校正 PRD**，否则会照着一份过时的地图施工。

## 4. 风险红线（做任何优化都不能碰）

核验中确认的一致性风险，**必须作为硬约束**：

1. **同一角色一致性**靠：身份基准网格（同一行=同一角色）、资产库、H3 公共参考图、跨集 `state_out`。任何**跨镜并发化/重排**必须保持逐镜参考图分配与预取锁语义（`_pf_lock`、3D 渲染进程级串行锁），否则「同镜双跑」或角色漂移。
2. **断点续跑**依赖**内容寻址缓存键**（含 prompt 全文、seed、cfg 判决字段）。**调参（关增强、改 timeout、改质检档）会改缓存键** → 已缓存前置段/增强结果失效、一次性变慢（不影响产物续跑）。
3. **3D 站位图是分镜 `<image1>` 构图基准**。硬关（`ENABLE_3D_BLOCKING_IMAGE=0`）省时但会改变构图一致性，建议保持「超时 + 去重试」而非硬关。
4. **「改了没生效」**：进程不热加载 + 桌面版资源镜像机制，改代码后须正确重启/重打包才生效（生效判据：进程启动时间 > 镜像文件 mtime）。**这条与 Phase 0.1 强耦合**。
5. **集号规则一旦改动，已有产物全部错位**，必须清掉重跑——涉及分集/编号的改动需单独评估回退成本。

## 5. 需要你拍板的决策点

1. **Phase 0.1 多副本同步**：是「实现自动同步脚本」还是「只把 `check_app_sync.py` 接成硬门禁 + 人工同步」？（影响后续所有改动的工作方式）
2. **C1 视频默认路径**：PRD 描述（整集一次、无拼接）与代码默认（按场次 + concat）——是**以代码为准改文档**，还是**期望回到整集模式**（产品意图）？
3. **G1 返工闭环方案**：走「多镜场自动整场重画」（改动中、见效快）还是「默认切段级导出」（改动大、更彻底）？
4. **Phase 2.2 提示词增强**：是否接受「关/降频」换取每集约 40 分钟提速（代价是失去 LLM 画面细化）？
5. **硬件**：是否安排内存/GPU 升级？（这是最高 ROI 但非代码项）

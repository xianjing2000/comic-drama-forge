## 0. 一句话结论

**第一轮外部借鉴解决的是「抄哪些功能」；这一轮的真正增量是三块：**

1. **推理吞吐加速层（命中唯一瓶颈）**——分镜图单镜中位 **343.6 s**、8 GB 显存 + 33 GB 内存是硬墙（§1.1）。第一轮的四份竞品文档**完全没碰推理加速**。这一层（ComfyUI 的 SageAttention / 少步蒸馏 LoRA（TurboLoRA）/ TeaCache / FP8）是零到中成本、直接打在瓶颈上的最大杠杆，且**同类项目 `comfyui-auto-drama` 已在同一 H3 模型上用了 TurboLoRA + SageAttention**——是「有同行验证过」而非纸面。
2. **自动评测层**——本项目质检很重（三态、教训库、软放行），但全是「生成器自评」。日志里缺陷榜首是「**面板雷同 573 次**」、其次「与上一镜不连续」，目前只能靠人工看片。引入**参考无关的一致性/多样性度量**（InsightFace 人脸余弦、CLIP/感知相似度、VBench 视频维度）可把「串脸 / 雷同」从主观变成可量化门禁。
3. **工程与产品化硬化**——多副本同步**工具已写好但门禁未接、`_backend` 副本已实测漂移**；进度 100% 轮询（**全仓零 SSE**）；结构化失败码 `failure_codes` **只进死信、不出圈到前端**；返工闭环在**多镜场降级为整场重画**。这些都是「低成本、直接改善可用性」的确定性收益。

**外加一条闭源借鉴路径**：本机 `D:\rea` 是一套逆向工程 MCP 工具（Electron/JS、原生二进制、APK、网页/网络流量），可用于拆解剪映/CapCut、即梦、可灵、星流、白日梦等**闭源同类产品**的「图文成片/一键成片」数据模型与提示词 schema——**但需要你指定 1–2 个具体目标**（见 §6 决策点）。

**硬约束（实测）**：RTX 5060 Laptop **8151 MiB 显存**、**31.43 GB 物理内存**；ComfyUI 以 `--lowvram --reserve-vram 1 --disable-pinned-memory` 启动；H3 视频模型 **19.53 GB** + H3 文本编码器 **14.61 GB** 均**超过物理内存可用余量** → RAM↔VRAM 两级搬运；内存耗尽窗口 **86 分钟/镜**（正常 3–6 分钟/镜）。GPU 闸门 `TASK_QUEUE_CONCURRENCY=1`（`config.py:208`）是**正确**设置，勿调大。

**缺口**：
- **无 VRAM/内存准入检查**——提交 GPU 任务前不探显存/内存余量（`gpu_task_gate.py` 只做并发=1 的信号量，`config.py:208`）。

- **3D 渲染锁覆盖不全**——`_TE3D_RENDER_LOCK` 只包住主渲染（`storyboard_helpers.py:2352-2358`），但基准图质检触发的「修计划重渲」在锁**之外**直调 `render_blocking_from_plan`（`:2379-2386`），与预取线程并发会抢回传单例。
- **增强层超预算线程不回收**——`prompt_enhance._call_with_budget`（`:209-241`）超预算后放弃等待但**线程仍在跑**，上游慢时可能堆叠。

## 2. 外部借鉴（v2）

### 2.0 与第一轮的关系

第一轮借鉴的对象是「**流程型**」开源项目（ViMax / ArcReel / Huobao / penshot / Toonflow / comfyui-auto-drama / NiliX / ai-manga-factory …），产出是**功能机制**（脚本/分镜/一致性/拼接），**已基本落地**。本轮借鉴分两路：

- **开源「技术型」项目**（模型加速、一致性算法、评测套件）——第一轮**完全没覆盖**，是本轮主线。
- **闭源产品**（用 `D:\rea` 拆解）——第一轮多为 README/架构描述，本轮给出**可执行的逆向路径**。

> **贯穿全节的方法纪律**（沿用第一轮教训）：每个借鉴项都必须标注**对本项目（ComfyUI + MiniMax H3 + 8 GB 显存 + 按场次拼接）的适配性**，分「✅ 可直接用 / 🟡 需 PoC 验证 / ⚪ 不适用或已有等价」。**禁止照搬数字与模型栈。**

#### C. 自动评测（★ 本项目最大空白——把「人工看片」变「可量化门禁」）

| 名称 | 链接 | 一句话价值 | 对本项目适配性 |
|---|---|---|---|

### 2.2 闭源借鉴：用 `D:\rea` 拆解同类产品

`D:\rea` 是 **REA（Reverse Engineer Anything）** 逆向工程工具（v6.5.0，MCP + CLI，MIT）——「看你想要的功能，拆到二进制级，再照做」。它能分析：**Electron/JS 应用**（模块/路由/IPC/原生插件关系）、**网页**（结构/脚本/网络观察）、**APK**（manifest/类/方法）、**原生二进制**（Hopper/Ghidra/IDA）、**HAR/SAZ/mitmproxy 网络抓包** 等。分析在本机进行。

**为什么适合本项目**：本项目很多「该怎么做」的问题（提示词 schema、时间线数据模型、一致性手段、失败处理、导出格式），闭源同类产品里已有成熟答案，`rea` 能把它们拆成可借鉴证据。

**候选目标短名单**（按「同类度 × 可拆性」排序，**需你指定 1–2 个**）：

| 目标 | 载体 | rea 路径 | 想回答的问题 |
|---|---|---|---|
| **剪映专业版 / CapCut 桌面** | Electron | `analyze_javascript_application`（对 `app.asar`） | 「图文成片/一键成片」的**分镜→时间线数据模型**、提示词编排、导出格式 |
| **即梦 / 可灵 / 星流（Web）** | 网页 | `capture_browser_scenario` + `inspect_web_network_capture` | 提示词/API schema、参数、能力边界（哪些是本地做不到的） |
| **剪映 / 快影 / 白日梦（App）** | APK | `inspect_android_package` | 移动端「一键成片」流程与一致性处理 |
| **任意本地 Electron 漫剧工具** | Electron | `analyze_javascript_application` | 直接对标其分镜/一致性/导出实现 |

**通用分析路径**（`rea` 的 staged workflow）：

1. **列问题清单**：如「它怎么做多镜一致性」「它的分镜 JSON 长什么样」「失败如何自愈」「导出到剪映的格式」。
2. **路由目标**：Electron→`analyze_javascript_application`（先 `detail:"summary"`）；网页→浏览器观察；APK→`inspect_android_package`。
3. **顺藤摸瓜**：从入口（如「一键成片」按钮）跟到数据流与状态变化；必要时 `trace_application_feature`。
4. **佐证**：静态读不出行为的，用**网络抓包**（先跑一遍，HAR/SAZ）看真实请求/响应。
5. **结论落地**：把「观察到的行为」与「我们的设计选择」分开，写成可实施的借鉴点（**同样走「先核实再照搬」纪律**）。

**前置条件与边界**：
- `rea` 需 `npx rea-agents setup` 注册 MCP；远端分析可选装 Hopper/Ghidra，**静态 JS/Electron 分析不需要原生引擎**；Node ≥ 22.19。
- **合法边界**：`rea` 仅用于「你拥有或获授权分析」的软件（见其 DISCLAIMER.md）。拆解**仅用于学习机制/互操作**，不复制受版权保护的资源/代码。
- **我可执行的前提**：需要你**指定具体目标**（哪个应用、在哪、你是本机已装还是给 URL）。当前会话未注册 rea MCP，需先 setup 后重启会话才能实际跑（见 §6 决策点）。

## 5. 风险红线（做任何优化都不能碰）

沿用 `docs/优化规划_PRD落地路线图_20261016.md` §4 的硬约束，并新增两条：

1. **同一角色一致性**靠「身份基准网格（同一行=同一角色）/资产库/H3 公共参考图/跨集 `state_out`」。任何**跨镜并发化/重排**必须保持逐镜参考图分配与预取锁语义（`_pf_lock`、`_TE3D_RENDER_LOCK`），否则「同镜双跑」或角色漂移。⚠️ 注意 §1.3 已发现的 **3D 锁覆盖不全**（`storyboard_helpers.py:2379-2386` 在锁外重渲）——顺手修掉。
2. **断点续跑依赖内容寻址缓存键**（含 prompt 全文、seed、cfg 判决字段）。**改 LoRA/步数/量化/超时/质检档都会改缓存键** → 已缓存的前置段/增强结果失效、一次性变慢（不影响产物续跑）。**B-2/B-4/B-7 都踩这条，务必先小范围验证。**
3. **3D 站位图是分镜 `<image1>` 构图基准**。硬关会改变构图一致性；保持「超时 + 去重试」而非硬关（B-3）。
4. **「改了没生效」**——进程不热加载 + 桌面版资源镜像。**改 `app/` 代码后必须同步四处副本**（`app/` 正本、`electron-app/_backend/app`、安装区 `resources/backend`、运行镜像 `%APPDATA%\mjscxt-desktop\resource-mirror\app`），生效判据=进程启动时间 > 镜像 mtime。**这是 A-1 的前置，也是本清单标「同步」行的强制项。**
5. **集号规则一旦改动，已有产物全部错位**，须清掉重跑——涉及分集的改动单独评估回退成本。
6. **【新增】闭源拆解的合法边界**：用 `rea` 仅分析「你拥有/获授权」的软件，产出仅用于学习机制与互操作，**不复制受版权保护的资源/代码**。
7. **【新增】提速改动先在单镜/单场小范围验证**（同 seed 同 prompt A/B），通过再全量——避免「一改全崩 + 缓存全废」。
